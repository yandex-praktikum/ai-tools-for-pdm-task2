# Правила данных `flight_ops_lab`

Данные полностью синтетические и предназначены только для учебных задач этого урока.

## Граница набора

* Целевой стек: PostgreSQL 16. Все временные метки набора приведены к часовому поясу `Europe/Moscow`, независимо от аэропорта.
* После выполнения `schema.sql` и `seed.sql` разрешены только читающие запросы.
* Направление рейса ориентированное: пара `departure_airport_id -> arrival_airport_id`. Обратный маршрут является другим направлением.
* Московский аэропорт определяется точным значением `airports.city = 'Moscow'`, а не списком идентификаторов.
* Стабильный идентификатор аэропорта — `airport_id`; человекочитаемые поля — `airport_code` и `airport_name`.

## Детализация таблиц

| Таблица | Одна строка | Основной идентификатор |
|---|---|---|
| `airports` | один аэропорт | `airport_id` |
| `aircraft` | один самолёт | `aircraft_id` |
| `flights` | один рейс | `flight_id` |
| `passengers` | один синтетический пассажир | `passenger_id` |
| `bookings` | одно бронирование пассажира на рейс | `booking_id` |
| `boarding_passes` | одна регистрация по бронированию | `boarding_pass_id`; связь через уникальный `booking_id` |

## Статусы, даты и `NULL`

* Фактический словарь `flights.status`: `Scheduled`, `Completed`, `Delayed`, `Cancelled`.
* Выполненный рейс для заданий 10, 13 и 14 имеет статус `Completed` или `Delayed` и обе непустые фактические временные метки.
* У `Scheduled` и `Cancelled` обе фактические временные метки равны `NULL`. Это ожидаемое состояние, а не автоматическая ошибка.
* Задержка отправления равна `actual_departure - scheduled_departure` в минутах.
* Для сравнения задержек учитываются только выполненные рейсы. Рейс считается задержанным, если задержка отправления строго больше 15 минут.
* Средняя задержка считается только по задержанным рейсам; число учитываемых выполненных рейсов и число задержанных показываются отдельно.

## Параметры заданий

* Задание 8: минимум `4` рейса на направление, граница включается (`>= 4`).
* Задание 9: полуинтервал от `2026-03-03 00:00:00+03` включительно до `2026-03-08 00:00:00+03` исключительно. Фильтр применяется к `scheduled_departure`.
* Задания 14 и 15: низкая заполняемость означает значение строго меньше `0.60`.

## Бронирование, регистрация и посадка

* Единица счёта в задании 12 — уникальное подтверждённое бронирование `bookings.booking_id` со статусом `Confirmed`.
* Регистрация подтверждена наличием связанной строки `boarding_passes`.
* Посадка подтверждена непустым `boarding_passes.boarded_at`.
* Потеря между этапами равна разнице числа сущностей. Относительная потеря делится на число сущностей предыдущего этапа.
* В наборе есть подтверждённые бронирования без регистрации, регистрации без посадки и один пассажир без бронирования. Внешние ключи-сироты отсутствуют.

## Заполняемость и профиль направления

* Фактическая заполняемость выполненного рейса: число уникальных пассажиров с подтверждённой посадкой, делённое на `aircraft.capacity` этого рейса.
* Для маршрута объём наблюдений — все рейсы направления.
* Доля задержек: задержанные выполненные рейсы / все выполненные рейсы направления.
* Доля отмен: рейсы со статусом `Cancelled` / все рейсы направления.
* Средняя заполняемость: среднее из показателей заполняемости выполненных рейсов направления.
* Доля низкой заполняемости: выполненные рейсы с заполняемостью `< 0.60` / все выполненные рейсы направления.
* Критерии риска для задания 14: доля задержек `>= 0.50`, доля отмен `>= 0.25` или доля низкой заполняемости `>= 0.50`. Каждый критерий оценивается отдельно.
* В задании 15 допустимо выбрать маршрут по заранее сформулированному правилу, опирающемуся на эти метрики, или доказать, что правило не выделяет один маршрут. Reference-решение hidden-слоя не является единственно допустимым.
