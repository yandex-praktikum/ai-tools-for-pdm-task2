# Правила работы с кейсом OrbitDesk

Откройте пакет в IDE-агенте, который вы выбрали для прохождения курса. Используйте только один агент. Не подключайте к аудиту второго агента и не передавайте ему выводы первого как доказанные факты.

## Цель

Проверить пять опубликованных гипотез по исходным данным и зафиксировать человеческое решение в `release-decision.md`.

## Источники истины

Используйте только:

* материалы в `input/`
* запросы в `checks/`
* результат `npm run audit`
* критерии из `audit-checklist.md`

Ответ агента, текст отчёта и технический статус раннера сами по себе не являются доказательствами.

## Разрешённые действия

* читать все файлы пакета
* выполнять только читающие запросы SQL
* выполнить `npm install` и `npm run audit`
* заполнять `release-decision.md`
* объяснять связь между гипотезой, запросом SQL, исходными строками и определением метрики

## Неизменяемые материалы

Нельзя изменять, удалять или заменять файлы в `input/`. Нельзя подменять отсутствующие данные предположениями.

Не изменяйте `checks/`, `scripts/` или `package.json` во время основной попытки. Если после аудита потребуется экспериментальная правка, агент сначала должен показать:

1. цель правки
2. доказательство проблемы
3. затрагиваемые файлы
4. ожидаемый эффект
5. способ повторной проверки

После подтверждения человеком эксперимент выполняется только в отдельной рабочей копии пакета. Исходный пакет остаётся контрольным.

## Стоп-условия

Остановитесь и зафиксируйте риск, если:

* схема базы расходится с `input/schema.md`
* определение метрики расходится с `input/metric-definitions.md`
* версия набора данных не совпадает с указанной в базе
* запрос требует отсутствующего источника
* агент предлагает изменить исходники до показа плана

## Граница решения

Раннер заполняет только техническую таблицу. Итоги гипотез и статус `publish`, `hold` или `rework` формулирует человек после проверки доказательств.
