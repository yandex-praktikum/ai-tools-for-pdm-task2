# analytics-audit-case

Проверка пяти опубликованных гипотез по исходным данным и фиксация человеческого release-решения в `release-decision.md`.

## Требования

* Node.js 20 или новее и npm (сборка проверена с Node.js `v22.18.0` и npm `10.9.3`)
* Ожидаемая версия набора данных: `v2`

## Запуск

```bash
npm install
npm run audit
```

Раннер (`scripts/run-audit.mjs`) читает базу SQLite, выполняет проверочные запросы из `checks/`, сверяет версию набора данных и записывает техническую таблицу со статусами `pass`, `fail` или `not-checkable` в `release-decision.md` между маркерами `AUDIT_RESULTS_START` / `AUDIT_RESULTS_END`. Итоговый статус `publish`, `hold` или `rework` раннер не выбирает — его формулирует человек.

## Состав пакета

* `input/` — неизменяемые исходники: отчёт, гипотезы, определения метрик, схема, контрольные количества и база `orbitdesk-audit.sqlite`
* `checks/` — пять подготовленных проверочных запросов SQL (по одному на гипотезу H-01…H-05)
* `scripts/run-audit.mjs` — готовый раннер аудита
* `release-decision.md` — шаблон решения с технической таблицей
* `AGENTS.md` — правила работы с кейсом для IDE-агента
* `audit-checklist.md` — критерии самопроверки

## Ограничения

* Файлы в `input/` нельзя изменять, удалять или заменять — раннер проверяет их хеши до и после запуска.
* `checks/`, `scripts/` и `package.json` не изменяются во время основной попытки.
* Отсутствующие данные не достраиваются предположениями: недостаток доказательств — самостоятельный результат проверки.

Подробные правила и стоп-условия — в `AGENTS.md`, критерии приёмки — в `audit-checklist.md`.
