# Спецификация анализа LearnFlow

## Вопрос решения

Достаточно ли наблюдения по `first_lesson_recommendation_v2`, чтобы выбрать следующий ограниченный продуктовый шаг?

## Определения до расчёта

- **Единица наблюдения:** один уникальный `user_id`.
- **Воронка:** `sign_up → diagnostic_started → diagnostic_completed → recommendation_viewed → lesson_started → lesson_completed → trial_started`.
- **Правило этапа:** пользователь учитывается один раз по первому событию типа, а следующий этап засчитывается только после предыдущего.
- **Окно основной метрики:** семь суток от `experiment_assignments.assigned_at`, правая граница включена.
- **Основная метрика:** доля однозначно назначенных пользователей варианта, завершивших первый урок после `lesson_started` и не позднее семи суток после назначения.
- **Защитная метрика:** доля пользователей с пробным периодом, отменивших его не позднее 72 часов после `trial_started_at`.
- **Сегмент:** `platform = 'ios'` — единственный заранее выбранный срез.

## Качество данных и границы вывода

- Пользователь с неоднозначным назначением не входит в основную метрику.
- Событие с нарушенным порядком не входит в числитель, а отсутствие назначения не превращается в вариант.
- Наблюдаемая разница не является доказанным причинным эффектом без достаточного объёма и утверждённого критерия неопределённости.
