# Схема и словарь метрик FitFlow

Все даты используют формат ISO `YYYY-MM-DD`. Все денежные поля хранят целые
центы.

## Таблицы

| Таблица | Уровень строки | Важные поля |
|---|---|---|
| `marketing_spend` | Один канал и один период привлечения | `channel`, `period_start`, `period_end`, `spend_cents` |
| `customers` | Один зарегистрированный клиент | `customer_id`, `acquisition_channel`, `registered_at` |
| `subscriptions` | Одна подписка | `subscription_id`, `customer_id`, `started_at`, `ended_at` |
| `payments` | Один успешный платёж | `payment_id`, `customer_id`, `paid_at`, `amount_cents` |
| `refunds` | Один возврат, связанный с платежом | `refund_id`, `payment_id`, `refunded_at`, `amount_cents` |
| `variable_costs` | Затраты на одного клиента за месяц | `cost_id`, `customer_id`, `cost_month`, `amount_cents` |

Поле `subscriptions.ended_at` допускает `NULL`: это означает, что на дату
окончания наблюдения не зафиксирована дата завершения. Его нельзя трактовать
как ноль или дату.

## Утверждённые определения

* **Новый клиент:** строка в `customers`, у которой `registered_at` попадает в
  период привлечения. Это отдельное определение пути клиента; для CAC в этом
  проекте используется определение нового платящего клиента.
* **Новый платящий клиент:** уникальный клиент, чья первая успешная оплата
  попадает в период привлечения. Канал берётся из `customers.acquisition_channel`.
* **Чистая выручка:** успешные платежи когорты новых плательщиков в горизонте
  наблюдения за вычетом возвратов за тот же горизонт, связанных с этими платежами.
* **Активный клиент-месяц:** одна строка `variable_costs` для нового платящего
  клиента и месяца наблюдения. В учебной базе есть по шесть строк для каждого
  платящего клиента.
* **Месячный ARPU:** чистая выручка, делённая на число активных клиент-месяцев.
* **Месячная маржинальная прибыль на клиента:** чистая выручка за вычетом
  переменных затрат, делённая на число активных клиент-месяцев.
* **Наблюдаемый `LTV_6m`:** чистая выручка за вычетом переменных затрат за
  фиксированный шестимесячный горизонт, делённая на число новых платящих
  клиентов.
* **LTV/CAC:** наблюдаемый `LTV_6m`, делённый на CAC. Это описательный
  показатель учебного кейса; он не сравнивается с внешним бенчмарком.
* **Ориентировочный срок окупаемости CAC:** CAC, делённый на месячную
  маржинальную прибыль на клиента. Он не определён при нулевой или отрицательной
  марже и не прогнозирует удержание за пределами горизонта наблюдения.

## Периоды и округление

* Период привлечения: с `2025-01-01` по `2025-01-31` включительно.
* Горизонт наблюдения: с `2025-01-01` по `2025-06-30` включительно.
* Для каналов используются одинаковые границы и определения.
* Промежуточные значения не округляются. `calculate.mjs` хранит денежные
  значения как целые центы и применяет правило half-up до двух знаков только
  при выводе.
