# Правила данных

* Одна строка `subscriptions` описывает одну подписку. Единица подсчёта — уникальный `subscription_id`, а не событие и не пользователь.
* Подписка считается активной, только если `status = 'active'` и `ended_at IS NULL` одновременно.
* `NULL` в `status` не означает активность. Строка со `status = 'active'` и заполненным `ended_at` также не считается активной.
* Тариф хранится в `users.tariff`. Для ответа нужно соединить `subscriptions.user_id` с `users.user_id` через `INNER JOIN`.
* Таблица `events` не нужна для текущего вопроса. Её присоединение размножит строки подписок, потому что у пользователя может быть несколько событий.
* Контроль уникальности пользователей служит диагностикой соединения. Он не заменяет единицу подсчёта активных подписок.
* Результат должен содержать тариф и количество активных подписок. Вывод относится только к этой синтетической базе и не объясняет причины различий.
* Разрешены только запросы чтения. Изменять схему, строки базы или файлы проекта нельзя.
